# 范围与决策基线

状态：已确认的需求基线与待验证设计，非软件验收报告。日期：2026-10-28，时区 Asia/Shanghai。

## 1. 来源与优先级

正式来源为 [requirements.md](source/requirements.md) 和 [supporting-deliverables.md](source/supporting-deliverables.md)，均为 v0.7。原始来源、版本和校验值见 [manifest.json](source/manifest.json)。

用户进一步确认：严格遵循两份文档；每 publication × language 独立 Ghost；尽量保持原版以跟随上游升级；当前目录作为全新项目处理。旧技术材料不作为启动依赖。若以后提供旧材料，应与当前基线比对，不能恢复已经被 v0.7 替代的约束。

明确被替代的旧约束：额外 Editor／强制第二人审核、NyxID 仅操作草稿、只能在 CMS 确认发布、指标可选。

## 2. 目标与场景

Goal：个人或组织能够经 CMS 或 NyxID 完成双语 Markdown 创作、确认发布、外部分发和指标查询，并具备隔离、审计及恢复证据。

| 使用者 | 必须完成的场景 |
| --- | --- |
| 无组织的个人 | 拥有独立个人空间、博客和连接，发布个人文章，查询个人指标 |
| 普通组织成员 | 保留全部个人能力，管理自己的组织草稿并提交，查看组织聚合看板 |
| 指定 Publisher | 发布自己的或已提交的组织稿件；组织外部自动写入仍满足 NyxID Admin 授权要求 |
| 组织 Admin | 管理发布角色并发布组织内容；不因此获得成员私人草稿或指标访问权 |
| 多组织成员 | 显式选择 owner 和渠道；离开一个组织不改变个人及其他组织的所有权 |
| 委托客户端／Agent | 在调用人的授权范围内独立完成服务操作，不强制跳回 CMS |
| 平台运维 | 配置站点、维护与恢复；特权访问需要披露和留痕 |

## 3. 交付范围

D1 独立平台、自托管 Ghost 与 NyxID 登录；D2 可调用的 NyxID 服务；D3 个人／组织空间及权限；D4 双语 Markdown 编辑与原文访问；D5 投稿与原文发布；D6 四个平台支持；D7 发布生命周期看板；D8 阅读与分发指标；D9 运维交接及实际验收证据。

全部 D1–D9 必须完成。可以分批上线，但试点不能称为全量交付。DEV 个人／组织及 Hashnode 组织自动发布不可擅自改成人工方式。

Non-goal／暂不选择的可选项：定时发布、自助工作区和站点开通、自动自定义域名、个人 Hashnode、额外语言和平台。没有定时功能时，延迟分发到期后由人再次触发；待执行任务的取消仍为必需。

独立本地登录、NyxID 故障期间持续认证使用、重复的供应商直连凭证路径不属于交付范围。英文与简体中文原创必需；外部分发初期仅英文，中文须先验证平台政策和渲染。

## 4. 已确定的架构边界

| 决策 | 依据与取舍 |
| --- | --- |
| 原版 Ghost，业务平台外置 | 遵循用户的上游升级要求，避免维护核心／Admin 补丁；我们仍需维护 API Adapter、配置及主题 |
| 每 publication × language 独立实例 | D1 明文要求；双语两个实例，成本和容量按总实例数计算 |
| 单一业务层供 CMS 与 NyxID 调用 | R2、R10 要求两个入口同权限同数据，避免复制权限逻辑 |
| 平台保存 Markdown 和不可变发布版本 | R5 原文保真、R4 草稿与线上分离；Ghost 作为公开发布目标 |
| 所有者、署名作者、操作者分别建模 | R3 要求个人／组织权属与署名分离 |
| 官方扩展路线优于 fork Ghost | fork 初期可复用后台但升级耦合高；官方 API 外置平台开发量较大但边界更稳定 |

## 5. 合理默认与尚待验证的事项

以下为设计候选，不是新增的已确认业务承诺。涉及权限开放的默认采用最小授权，测试前不扩权。

- 组织成员与 Admin 身份以 NyxID 的当前权威查询为依据；Publisher 是平台内由组织 Admin 管理的业务权限。验证实际查询契约和撤权处理后定稿，不能只相信过期 token 中的角色。
- 未提交的组织稿默认仅作者操作；其他发布者仅对提交的确定版本执行发布。离职稿接管与其他成员改写权限不从“组织 Admin”身份自动推导，需补充显式规则。
- 草稿修改产生新 revision；已提交的旧 revision 保持冻结，新 revision 需要重新提交或由有权发布者确认。批准和发布必须指向具体 revision。
- 初始站点运营协助开通；不假设首发 owner 数或开放注册容量。publication 数量与域名拓扑由实际开通清单决定。
- UI 的双语覆盖范围、日期时区、隐私同意政策、数据保留、指标更新频率、RPO／RTO、容量和付款责任人需在上线验收前量化。
- NyxID 的调用人身份、精确连接选择、组织权限和 Admin 精确授权必须联调确认；文档能力不等于目标环境已部署。

## 6. 里程碑、依赖与预算

| 阶段 | 交付内容 | 门槛 |
| --- | --- | --- |
| 0 | 需求基线、实验环境、身份与发布集成验证 | 高风险路径有实际证据，依赖和缺口归属清楚 |
| 1 | 内容／权限底座、双语编辑、统一业务 API | owner 隔离、原文保真、版本与冲突测试通过 |
| 2 | CMS／NyxID 原文发布、Ghost 映射与基础指标 | 正确版本公开可访问，私有素材不泄漏 |
| 3 | 外部分发、修订／移除、完整状态与指标 | 必需自动连接器真实验证，异常对账可恢复 |
| 4 | 故障、恢复、运维、全量验收 | D1–D9 运行证据齐备，所有未通过项明示 |

外部依赖：NyxID 环境与注册权限、真实测试身份及组织、DEV 授权账号、符合条件的 Hashnode Pro publication、Medium／HackerNoon 账号和人工操作负责人、测试内容发布授权、HTTPS 域名及基础设施、订阅／托管付款方。

粗估假设为成熟编辑器复用、无迁移、人工开通、NyxID 已有能力可复用；此前给出的 20–30 研发人周另加测试运维仅供预算讨论，阶段 0 后重估，非承诺排期。基础设施成本 = 平台固定成本 + 各语言 Ghost 实例成本 + 数据库／存储／备份／流量／指标 + 外部订阅 + 运维。公开流量与 owner 数未给定，不虚构月费。

## 7. 指标与上线控制

建议北极星指标：每周成功发布的活跃 owner 数。业务观察指标：完成发布耗时、按目的地统计的分发成功／待处理情况、可归因回访。护栏：越权与泄密事件、重复副本、发布失败率、指标延迟、恢复用时与恢复数据窗口。

先在受控个人／组织工作区灰度。连接器有独立开关；第三方故障返回明确待处理状态，不阻断原创发布和已公开页面。回滚应用前停止新任务准入并保留审计与对账记录。Ghost 升级先做兼容性验证和备份；发生数据库迁移时不能仅降镜像，需按恢复手册恢复匹配的数据与配置。已经写入外部平台的文章通过纠错／移除流程处理，不能靠应用回滚撤销。
