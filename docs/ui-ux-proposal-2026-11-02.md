## 2. 现状诊断

现有 CMS 已接入真实业务操作，主要问题是信息架构、任务顺序与反馈方式。

| 现状 | 使用影响 | 设计处理 |
| --- | --- | --- |
| 编辑、发布、分发、指标和权限管理集中在同一页 | 写作时被低频操作干扰，页面随功能增加持续变长 | 应用导航分区，编辑器独立页面，复杂操作按需展开 |
| 文章列表仅显示语言和标题，前端未提供分页入口 | 难以辨认待发布稿件、线上版本及译文状态 | 增加内容摘要、状态筛选、分页和语言关联 |
| 发布、更新、下线、取消、对账并排 | 难以判断当前应该执行哪一步 | 按权限和当前状态提供一个主要动作 |
| 分发需要选择 release、delivery、copy、approval reference 等 | 用户承担内部对象之间的关联工作 | 从当前文章／版本和目标平台进入，系统关联对象，详情保留诊断信息 |
| 冲突仅反馈错误文本；预览是已保存版本 | 容易误解预览内容，冲突恢复缺少引导 | 显示版本标识，保留本次编辑，提供重新加载／比较路径 |
| 指标有数字和表格，但混在编辑器下方 | 数据阅读和内容创作相互干扰 | 独立分析页和文章级数据入口 |
| 权限管理需要输入成员 subject；前端仅获得 canPublish | Publisher 和 Admin 的操作入口不够准确 | 后端提供细分 capability 与授权成员展示信息 |

证据：[现有页面](https://github.com/aelf-hzz780/chronoai-cms/blob/6ea9ecdd4b075c3a6917d55b699e7200c171583f/web/index.html)、[前端交互](https://github.com/aelf-hzz780/chronoai-cms/blob/6ea9ecdd4b075c3a6917d55b699e7200c171583f/web/app.js)、[接口](https://github.com/aelf-hzz780/chronoai-cms/blob/6ea9ecdd4b075c3a6917d55b699e7200c171583f/src/app.ts)。

## 3. 目标、用户与边界

### Goal

1. 明确当前工作区、内容所有者、署名作者、语言和可执行操作。
2. 顺畅完成「写作 → 保存版本 → 发布或提交 → 分发 → 查看结果」。
3. 清楚表达草稿、已提交版本、线上版本和外部副本之间的关系。
4. 让失败、待授权、人工操作和结果未知都有明确下一步。
5. 沿用 NyxID 当前品牌语言，兼顾长文编辑与高密度管理。

### 用户场景

| 使用者 | 核心任务 | UI 必须保留的边界 |
| --- | --- | --- |
| 个人作者 | 写作、发布个人文章、分发、看个人数据 | 不需要组织发布权限；其他组织 Admin 不能查看私人草稿或指标 |
| 普通组织成员 | 写组织草稿并提交，查看组织聚合数据 | 主动作是提交发布；不能更新或下线组织线上内容 |
| Publisher | 发布自己的或已提交的组织版本，处理分发 | 不能因此查看其他作者未提交的新草稿；不自动获得角色管理权 |
| 组织 Admin | 发布、管理发布权限、处理组织连接授权 | 发布自身稿件无强制第二人审核；外部自动写入另需 NyxID 精确授权 |
| 多组织成员 | 在个人和多个组织间切换 | 切换工作区不改变已有文章归属；离开组织不影响个人内容 |

### Non-goal

首版不增加强制编辑审核层级、AI 写作／自动翻译、定时发布、自助建站、自动域名、个人 Hashnode 或全新媒体资源库。Ghost Admin 继续由受信任运维使用。公开博客主题可后续沿用视觉 token，本轮重点为 CMS。

CMS 与 NyxID service 必须共用权限和状态语义；合法 service 操作不要求返回 CMS 再确认。

## 4. 视觉方向

| 方向 | 特点 | 取舍 |
| --- | --- | --- |
| A：深色品牌工作台 | 靠近 NyxID 官网，黑灰背景、紫色强调，整体识别度强 | 夜间适合；长文写作和复杂状态仍需单独优化对比度 |
| **B：NyxID 双主题内容工作台（推荐）** | 使用相同品牌色、字体与组件语言，工作区支持浅／深色，正文注重阅读 | 多一套主题验证成本，但兼顾品牌一致性和使用习惯 |

原型先以浅色工作区验证布局，同时提供深色关键页对照；默认跟随系统，允许手动选择。登录欢迎页可采用深色品牌表达。

已核实的 NyxID 当前实现：主色 `#5A2AF1`；辅助紫 `#A672FB`；Mona Sans 与 JetBrains Mono；官网背景 `#0D0D0D`。浅色工作台使用 `#F4F4F5` 画布和白色卡片；深色工作台使用 `#17171A` 画布、`#222225` 卡片和 `#141416` 侧栏。[当前 token](https://github.com/aelf-hzz780/NyxID/blob/defa7e50e7f9a058748c3b20c402f580770d6562/frontend/src/app.css)

旧 DESIGN.md 和 designs/blog 静态稿中的部分字体／配色已与当前实现不同，设计资产以当前代码核验为准。NyxID 公开博客的 mock 数据与 Directus 设想也不改变本项目既定的 Ghost 架构。

CMS 的具体建议：

- 4px 间距基准；以 8／12／16／24px 组织控件和区块。
- 桌面侧栏约 216–240px，可折叠；顶部约 56px；属性侧栏约 300–320px，可关闭。上述为 CMS 候选尺寸。
- 控件文字 14px 左右；正文编辑 16px 左右，行高 1.7–1.8；中文采用可用系统字体 fallback。正文预览保持适合长文阅读的行宽。
- 紫色用于主操作、选中态和品牌；绿／橙／红用于状态，并同时显示文字与图标。
- 编辑页减少阴影与装饰；发布确认用侧栏或对话框。登录页可有品牌氛围图，写作区保持静态。
- 键盘可达、明确焦点、表单标签、保存状态可被辅助技术读取；小屏表格改卡片，编辑与预览改为标签切换。无障碍需实际验证，不能由配色直接宣称达标。

## 5. 信息架构与首版页面

全局顶部持续显示「工作区名称／个人或组织／当前权限」。工作区切换仅切换可见数据；新建文章时确定 owner，不能把这个控件表现为已有文章的归属修改器。

| 页面 | 核心内容 | 优先级 |
| --- | --- | --- |
| 登录／进入工作区 | Sign in with NyxID、加载、登录失败、无已开通工作区提示 | P0 |
| **内容**（默认首页） | 新建／导入、搜索、分页、我的草稿／待发布／已发布筛选；标题、作者、语言、状态、更新时间 | P0 |
| **文章编辑／详情** | Markdown、私有预览、图片、版本、关联译文、保存／提交／发布入口 | P0 |
| **发布确认与结果** | 固定版本、所有者、署名、语言、原文站点、权利确认、执行结果 | P0，作为文章内流程 |
| **分发与待办** | 按文章／平台展示待授权、待人工、已提交、已发布、失败和待核验 | P1 |
| **数据分析** | 阅读趋势、热门内容、来源、分发结果；工作区和文章级筛选 | P1 |
| **设置** | 授权范围内的发布权限管理、NyxID 连接状态、已配置站点信息 | P1 |

P0/P1 为设计与上线顺序，不减少 v0.7 必需交付范围。首版不增设独立的装饰性 Overview；内容页顶部用紧凑待办入口承接紧急任务。普通成员看自己的待处理事项，Publisher/Admin 才能看到其有权处理的提交稿。

文章级导航采用「编辑｜发布与分发｜数据｜历史」。全局分发中心解决跨文章待办，文章内视图解决某一篇稿件的完整状态。

## 6. 关键流程

### 6.1 创作与双语

进入工作区 → 新建／导入 Markdown → 编辑 → 保存版本 → 私有预览 → 发布或提交。

- 标题区域下持续显示 owner、语言、署名和保存状态。
- 编辑区域提供 Markdown 与预览切换；首版复用已保存版本的私有预览，明确标注「预览版本」。实时分屏预览作为后续独立增强。
- EN／中文以关联内容组展示，各自拥有草稿、提交和发布状态。当前底层仍是独立文章，不暗示同时保存或发布。
- 原文变化后显示「译文需要核对」，允许查看关联版本；不得静默替换译文。
- 明确显示「线上版本」与「当前草稿」，例如“线上：已确认版本；草稿：有未发布更改”。保存不会更新线上。
- 409 冲突时保留当前编辑，解释服务器已有新版本，提供比较或重新载入路径；不能自动覆盖。
- 首版保留明确保存和离开保护。自动保存需另行确定修订生成、冲突和私有数据保存策略。

### 6.2 原文发布

个人作者／组织 Publisher／Admin：保存 → 私有预览 → 发布确认 → 等待核验 → 查看公开页面。

普通组织成员：保存 → 提交确定版本 → 显示“已提交，等待有发布权限的成员处理”。后续新编辑不会改动已提交版本。

发布确认摘要必须展示：

1. 内容所有者与署名作者，分别标注。
2. 标题、语言和具体已保存版本。
3. 目标原文站点；一组双语站点在 UI 中呈现 EN／中文入口，不要求作者理解 Ghost 实例拓扑。
4. 文字和图片权利确认。
5. 本次动作为首次发布、更新或下线，以及影响范围。

只对当前可执行操作展示主按钮。下线等高影响操作展示影响确认。新建或更新外部副本前，核验原文仍公开且版本符合要求；移除已知副本及只读核验不要求原文仍在线，但继续校验当前权限、精确连接及适用批准。

### 6.3 外部分发

新建／更新副本：核验原文及版本 → 选择目标和精确账号 → 确认副本内容／形式／动作 → 根据目标进入自动写入或辅助投稿 → 跟踪各平台结果。移除和只读核验从已知副本记录进入，原文下线后仍保留相应入口。

| 目标 | UX 方式 | 必须说明 |
| --- | --- | --- |
| DEV | 自动发布卡片 | 个人／组织、实际连接账号及可执行权限 |
| Hashnode | 自动发布卡片 | 组织 publication、Pro 与账号权限；个人支持不在本轮范围 |
| Medium | 辅助导入／投稿卡片 | 准备材料、打开平台、记录提交、核验公开链接 |
| HackerNoon | 辅助投稿与审核进度卡片 | 公司账号要求、编辑审核、不能保证接受 |

以上是 v0.7 的支持目标；具体可用性以目标环境及真实账户验证为准。

组织自动外部写入需 NyxID Admin 对确切内容、目的地和动作授权。这与 Ghost 原文发布权限分开呈现；不引入强制第二人编辑审核。修改内容／目的地／动作后，旧批准不能被当作新请求的批准。

日常操作不要求手填 approval reference；系统通过已有请求／关联能力引导处理，引用与 Trace ID 放入详情。真实批准状态与跳转能力需联调后确定，不承诺尚不存在的一键闭环。

| 状态 | 展示与下一步 |
| --- | --- |
| 等待组织授权 | 说明等待哪类授权、对应内容和目标，提供已有能力支持的请求／查看入口 |
| 待人工操作 | 提供材料、平台入口、结果登记 |
| 已提交／审核中 | 明确尚未公开；跟进投稿结果 |
| 已发布 | 显示已核验链接、对应版本和更新时间 |
| 失败 | 解释具体原因与修复路径；仅在确认安全时提供重试 |
| 结果待核验 | 主动作是“核验结果”，核验前禁止重复写入 |
| 需人工跟进 | 解释更新／移除受限或原账号失效，保留跟进记录 |

每个目标独立反馈。一处失败不覆盖其他成功。连接失效指向 NyxID 的连接处理，不切换到其他账号，不增加 CMS 直接保管供应商凭证的路径。初期外部分发仅英文；中文需满足政策与渲染验证条件。

延迟分发不表现为自动预约：当前未选定时功能，明确说明到期后仍需人工再次执行。

### 6.4 数据与异常

数据分析页固定日期、文章、语言、目的地筛选，展示 PV、每日估算 UV、趋势、热门文章、来源以及分发结果。工作区指标和文章指标使用相同查询口径。

- 展示来源、更新时间与日期／时区口径。
- “Unavailable”、未采集、真实 0 值分别表达。
- 不生成跨平台去重读者数，也不把每日估算 UV 相加宣称为区间去重人数。
- 外部累计计数与 Ghost 区间流量区别标注；私有预览不计入阅读指标。
- 采集失败不阻断发布。

所有页面覆盖：首次空状态、无搜索结果、加载、离线／服务不可用、权限不足、权限已撤销、会话失效。错误先说明发生什么和下一步；诊断详情保留 Trace ID。重新认证与权限校验前不能继续敏感操作。

## 7. UI 改造与新增能力的边界

| 可复用现有能力 | 需要补充／核验的能力 |
| --- | --- |
| NyxID 登录、工作区、原文导入导出、私有图片、明确保存、已保存版本预览 | 更细的 UI capability：能否编辑／提交／发布／管理权限等；后端仍为最终授权来源 |
| 修订记录、冲突检测、译文关联和 stale 标记 | 内容列表中的提交／发布／分发摘要、状态过滤与完整分页 UX |
| 原文发布／更新／下线、取消、结果核验 | 有权限约束的 owner 级分发与待办聚合查询，避免前端逐篇拉取 |
| 自动／辅助分发请求、状态、历史和人工结果登记 | 成员展示名称／搜索、角色管理界面所需受限查询 |
| 指标筛选、趋势和来源数据 | 所有新页面对同一 API 口径与权限的覆盖验证 |

自定义 slug、SEO 标题／描述、封面不是现成编辑字段。当前实现自动生成 slug 和 metadata；若增加独立 SEO 面板，应单独扩展数据模型、API 和公开页验收。第一阶段可展示现有公开结果，不提供无法保存的设置。

实时预览、自动保存、版本 diff、可编辑 SEO 作为后续候选，不计入单纯样式调整。跨文章聚合只返回调用人有权查看的版本与状态，不扩大 Admin 对私人内容的访问权。

## 8. 里程碑、依赖与粗估

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| M1：结构与原型 | 组件 token、信息架构、内容列表／编辑器／发布确认／分发详情四张关键页及状态变体 | 个人、普通成员、Publisher、Admin 的核心路径和边界都能在原型演示 |
| M2：P0 实现 | 登录、工作区、内容列表、编辑、版本反馈、发布确认 | 正确 owner／版本发布，未保存保护，提交不改变线上，双语独立，权限不回归 |
| M3：P1 完整工作台 | 分发待办、平台操作、指标、设置 | 自动／辅助区别，未知结果核验，部分失败，指标不可用，连接和角色变化 |
| M4：增强与收尾 | 根据验证结果选择实时预览、diff、自动保存或 SEO | 每项增强有单独范围、接口和验收；不绕过原有交付门禁 |

仅针对本次 UI 增量的初步估算：设计与原型 5–8 设计人日；前端 12–18 研发人日；查询／capability 等后端补齐 4–7 研发人日；集成与可用性验证 5–8 测试人日。按一名前端、部分后端和设计／测试并行，约 3–5 个工作周，需接口盘点后重估。此估算不包括上游修复、真实平台验收等待、生产部署或全部 D1–D9 收尾，也不是承诺排期。

主要依赖：当前业务 API 的稳定契约、NyxID 身份／权限与连接能力、代表性测试身份、个人与组织的双语 Ghost、真实外部账号和允许发布的测试内容。

CMS 固定交付版本的台账仍将 R031、普通 NyxID 门户 Launch、真实外部平台和生产交付列为未闭合；本轮未复验最新 NyxID 是否已解除相关上游限制，实施前需重新核对。界面可以解释能力不可用和待处理原因，不能用“已完成”或“已连接”掩盖未验证的能力。[交付台账](https://github.com/aelf-hzz780/chronoai-cms/blob/6ea9ecdd4b075c3a6917d55b699e7200c171583f/docs/delivery-status.md)

## 9. 验证、指标与上线回退

北极星沿用“每周成功发布的活跃 owner 数”。UI 改造主要观察：找到目标稿件的耗时、首次成功发布耗时、关键任务完成率、分发待办处理时长、保存／发布错误率。先采现状基线，再用同一组任务对比，不能凭设计图声称提升比例。

护栏：越权或私密内容泄漏、错 owner／错版本发布、重复外部副本、未保存内容丢失均零容忍；另监测失败率和数据延迟。交互埋点不包含文章正文、私有素材、凭证或批准秘密。

关键验收任务：

1. 无组织用户可以独立完成个人中／英文发布。
2. 普通成员可个人发布、组织投稿，不能通过任何入口发布组织内容。
3. Publisher 只能处理其授权版本；Admin 的权限管理不会读取私人草稿或指标。
4. 用户能区分当前草稿、已提交版本、线上版本与译文是否需要更新。
5. DEV 自动与 Medium 辅助流程在原型和实际 UI 中不会被误认；submitted 不显示为 published。
6. 结果未知时不会出现可直接重复发送的主按钮；一个平台失败时其他结果保留。
7. CMS 与 NyxID service 的权限、状态、Markdown 和指标一致。
8. 键盘完成核心任务，窄屏无关键操作丢失，主题／状态／焦点对比度实测通过。

上线先在受控个人和组织工作区灰度；通过 UI feature flag 保留旧界面回退，同一套业务权限和状态模型继续执行。查询接口优先采用兼容扩展。回退 UI 不撤销已经公开的文章或外部副本；这些继续由原有更新、下线、核验和人工跟进流程处理。

## 10. 首批设计交付建议

先完成四张高保真关键页：**内容列表、双语编辑器、发布确认、文章分发详情**。每张同时覆盖关键权限与异常状态；分发详情至少包含“DEV 等待组织授权”和“Medium 待人工导入”两种情形。确认这组完整工作流后，再扩展跨文章待办、数据分析与设置。


## 2026-11-03 原型补充：界面语言与双语站点

CMS 默认英文，提供 English／简体中文界面切换。此偏好独立于文章语言、默认创作语言和公开站点阅读语言。界面切换不重建当前表单，不触发保存、发布或跳转。

按 supporting-deliverables.md D1，每 publication × language 为独立 Ghost 实例，一个双语 publication 对应两套 Ghost。统一 CMS 中的编辑器 EN／中文标签选择关联稿件，分别发布到英文站／中文站；不存在切换界面即翻译正文或同步发布两种语言的行为。原型在编辑器目标条、发布摘要、语言关系弹窗和发布站点设置中明确显示映射。组织和个人的示例站点也独立。

公开页切换语言相当于进入对应语言站点或已公开译文；未发布的译文保持私有。本机统一 hash 地址仅用于演示跨站体验，不能作为真实 Ghost 实例部署完成证据。本次改动限于静态原型与设计说明。
